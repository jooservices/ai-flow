Runbooks

Assumes: you are an Owner or Super Administrator, you can see the incident in Command Center or SA health, and AI Flow v4 is installed. Each page has the same three parts: symptom, cause and fix.

An incident opens once for each kind and subject while the condition holds, and closes by itself when the condition clears. Critical and warning incidents are emailed. The list below has one page for every kind the code raises.

KindSeverityIn short
backup_failurewarningThe scheduled encrypted backup failed
backup_restore_testwarningThe weekly restore test failed
flow_idlecriticalTickets are ready but no run started
config_pincriticalA project's stack has no pin in versions.lock
node_downcriticalA node stopped sending heartbeats
node_toolswarningA node misses tools for a project or its AI accounts
node_serviceswarningA node's test services (PostgreSQL, Redis) are unhealthy
node_no_aiwarningA node has no AI account
master_invalid_plancriticalThe master repeatedly returned an invalid action plan
ticket_stuckwarningA ticket failed three runs in a row
run_slowwarningA run passed its warning time
run_hard_limitcriticalA run passed its hard time limit
account_quotawarningAn AI account is out of quota, signed out or failing
quota_predictionwarningAn account may use its quota before the provider resets it
role_healthwarningAn AI account is switched off for a role after repeated failures
quota_highwarning or criticalAn account's usage window is at 90% or more
role_coveragewarning or criticalA role has fewer than two ready accounts
jira_authwarning or criticalJira is not connected or must be reconnected
version_skewwarningA node's release does not fit the control plane
fleet_rolloutcriticalA rolling node upgrade halted
fleet_rollbackwarning or criticalThe rollback after a halted rollout finished or failed
upgrade_blockedcriticalThe pre-upgrade check blocked a control upgrade
release_verificationcriticalA node rejected a release (checksum or signature)
canary_rollbackcriticalA canary release was rolled back
canary_under_observedinfoA canary was promoted with too few runs
openobserve_deliverywarningOpenObserve rejects event batches

The control plane opens these incidents from health checks and recorded events. The master cannot open or close incidents directly. Every kind it can raise has a page in this list.
