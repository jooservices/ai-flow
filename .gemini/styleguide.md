# AI Flow v4 review style guide

Review the v4 code (`aiflow/v4/`, `tests/v4/`, `docs/v4/`, `deploy/v4/`, `prompts/v4/`) against the rules below. Each rule
names the document it comes from in brackets. Do not comment on rules that are not listed here, and do not comment on
style that a linter or the code-quality gate already decides. The old flow outside `v4` is not reviewed against these
rules; avoid changes there unless the pull request asks for them.

## Layers and dependencies

- Routes map HTTP to a service call: paths, request and response validation, authentication. A route contains no
  business workflow and no SQL. Request bodies live in the feature's `bodies.py` or `models.py`. [docs/v4/architecture.md, docs/v4/event-architecture.md]
- A service holds the use case. It has no FastAPI import, no `HTTPException` and no SQL; it raises domain errors and calls
  its repository, its events and shared core. [docs/v4/event-architecture.md]
- A repository holds all SQL of one aggregate and returns frozen dataclasses from `models.py`, never raw dictionaries. [docs/v4/event-architecture.md]
- Entities and value objects are frozen dataclasses in `models.py` and depend on nothing else. [docs/v4/event-architecture.md]
- Dependencies point toward stable contracts. Control does not import worker or node. Runtime core does not import control.
  Adapters import none of control, worker or node. Do not add a reverse import to avoid a cycle; move the shared contract into core.
  [docs/v4/architecture.md, docs/v4/code-quality.md]
- Keep runtime state in a run, a service object, the database or a request context, not in mutable module globals. [docs/v4/architecture.md]
- Put a new feature in its feature folder (`routes`, `service`, `repository`, `models`, `events`, `listeners`). A reaction to a
  state change is a listener of a domain event. `control/api.py` does not grow. [AGENTS.md, docs/v4/event-architecture.md]
- Register new HTTP routers through the route discovery under `control/routes/`; do not add a central route list. [docs/v4/architecture.md, docs/v4/architecture-tests.md]
- Keep calls visible to the static documentation check: plain, explicit calls from route handlers, no indirection through
  dictionaries or tuples of functions for work that publishes events or writes audit rows. [aiflow/v4/core/docsite.py]

## SQL

- SQL appears only in data-access modules: feature `repository.py` files, `control/repositories/`, and the database boundary
  modules `control/db.py`, `control/platform/db.py`, `control/platform/session.py` and `control/platform/data/`. A SQL string
  anywhere else fails the `sql-boundary` check. [aiflow/v4/core/sql_boundary.py, docs/v4/architecture.md]
- Keep transaction boundaries explicit. A service receives the repository it uses. [docs/v4/architecture.md]

## Errors

- No `except Exception`, `except BaseException` or bare `except:` without a written reason. The reason is a comment of at
  least 12 characters after a dash or colon, on the handler line, the line before, or the first line of the body. A new
  unexplained handler, or a rise in the count per file, fails the `broad-except` check. [docs/v4/broad-except.md]
- Do not swallow errors. A failure is raised or recorded, not dropped. [docs/v4/code-quality.md]

## Function and file size

- A function is at most 80 lines and has McCabe complexity at most 12. Split a function that breaks either budget into
  services, rules or helpers before adding behaviour to it. [docs/v4/code-quality.md, docs/v4/architecture.md]
- A file over 1,500 lines must not grow, and a new text file over 1,500 lines fails the `giant-files` check. Put new feature
  code in a new module. [docs/v4/giant-files.md]
- Repeated code is a finding. Blocks of eight or more identical normalized lines under `aiflow/v4/` fail the
  `duplicate-blocks` check; reuse the shared helper instead of copying prompt setup, environment preparation, run-result
  handling, auth checks or persistence queries. [docs/v4/duplicate-blocks.md, docs/v4/architecture.md]
- Do not add code without a caller or a test tied to a requirement; remove dead paths instead of extending them. [docs/v4/architecture.md]

## Baselines

- The quality, broad-except and duplicate-block baselines may only shrink. A pull request that raises a count, adds an
  entry or adds a new violation fails. Lower a baseline with its own command; do not edit it by hand to pass. [docs/v4/code-quality.md, docs/v4/broad-except.md, docs/v4/duplicate-blocks.md]

## Generated files

- The route contract snapshot `tests/v4/fixtures/route-contract-snapshot.jsonl` changes when a route's method, path,
  authentication or response model changes. Regenerate it with `AIFLOW4_UPDATE_ROUTE_SNAPSHOT=1` and commit the diff. [docs/v4/route-contract-snapshot.md]
- The control API audit (`docs/v4/api-rest-audit.md`) is generated by `control/rest_audit.py`; regenerate it with
  `AIFLOW_WRITE_AUDIT=1` when routes change. [docs/v4/api-rest-audit.md]
- Golden response fixtures under `tests/v4/fixtures/` record the response shape of a route. Regenerate them with
  `AIFLOW_WRITE_GOLDEN=1` only for an intended response change and review the fixture diff. [tests/v4/test_golden_responses.py]
- The generated event catalogue in `docs/v4/events.md` is written by `AIFLOW_WRITE_EVENTS_DOC=1`. Do not edit it by hand. [tests/v4/test_events_doc.py]

## Documentation

- Every changed API route and every changed console screen comes with a documentation change in `docs/v4/` (a new
  `docs/v4/<topic>.md` for a new feature). A new topic adds one line under "Topics" in `deploy/v4/README.md`. [docs/v4/documentation-site.md, aiflow/v4/core/docsite.py, AGENTS.md]
- A feature for end users has a Command Center UI path. The CLI is for developers and CI only. [AGENTS.md, docs/v4/architecture.md]
- Documentation must not present a CLI command as the end-user path. [tests/v4/test_no_cli_docs.py]
- Console screens are `id="view-<name>"` in the console page and each needs its Help page. [aiflow/v4/core/docsite.py, docs/v4/documentation-site.md]

## Security and secrets

- Never print, log or commit secrets, tokens or the contents of `/etc/aiflow`. Flag any literal credential, token or key
  in code, tests, docs or fixtures. [AGENTS.md]
- Secrets are stored encrypted (`aiflow/v4/core/secretbox.py`). Do not add a secret-looking field to an event payload. [docs/v4/security.md, docs/v4/event-architecture.md]
- Text from users is escaped and cross-site requests are checked. [docs/v4/security.md, tests/v4/test_console_escaping.py]

## Tests

- Every acceptance criterion of a ticket has a test. A new architecture rule has a test in `tests/v4/test_architecture.py`
  that proves both a passing tree and a synthetic violation. [docs/v4/architecture-tests.md]
- Tests use the shared test services and their own per-test Redis prefix and database. Do not use a production or admin
  account. [AGENTS.md]
- Characterization tests pin the current behaviour before a refactor. A refactor that changes a response, a side effect
  or an audit text is a behaviour change and must say so. [docs/v4/architecture.md, docs/v4/jira_connect_mount-structure.md]

## Dependencies and commits

- Do not add a dependency unless the ticket asks for it, and `uv.lock` must match `pyproject.toml`. [AGENTS.md]
- Commit titles follow `type: Subject (KEY-1)` with a capital-letter subject and no full stop. [AGENTS.md]

## Review tone

- Report a finding only when it breaks a rule above or causes a defect. Skip wording, naming preferences and formatting
  that the tools do not require.
- Keep each comment to one rule, with the file and line and the rule's source.
